# Trail Camera Expert Export

Analyze a folder of trail-camera photographs locally and export one timestamped CSV containing object counts, person attributes, pose evidence, and transparent combinations of several small computer-vision models. A contact sheet with up to **20 diverse example images** is generated by default for visual review.

**No Gemma, Ollama, language model, API account, or image upload is required.** The main detector and pose models use an available NVIDIA GPU, with CPU fallback. The small person-attribute classifier uses CPU by default.

This is an experimental analysis and manual-validation tool. It detects people, bicycles, strollers, motorcycles, ATVs/UTVs, other vehicles, dogs, and backpacks, and estimates apparent body orientation. **Adult/child classification is not yet reliable:** native age predictions are retained for review, while the combined output marks every detected person's age as unknown. Direction describes apparent facing in a still image, not measured travel direction.

## Quick start on Windows

1. Install **64-bit Python 3.12** or 3.11. If Python is missing, this command installs the recommended version:

   ```powershell
   winget install -e --id Python.Python.3.12
   ```

   Alternatively, use the [official Python installer](https://www.python.org/downloads/windows/). Reopen the terminal after installation.

2. Download the repository using **Code → Download ZIP**, then extract it, or clone it:

   ```powershell
   git clone https://github.com/victorchina-ops/trailcam-expert-export.git
   cd trailcam-expert-export
   ```

3. Put your photographs in the repository's `images` folder. Subfolders are included by default.

4. Double-click **`run_analysis.cmd`**, or run it from PowerShell to keep progress and error messages visible:

   ```powershell
   .\run_analysis.cmd
   ```

The first run creates a local `.venv`, installs the tested dependencies, downloads and verifies the model weights, and analyzes the images. It does not modify your global Python packages. The first setup needs an internet connection and can take considerably longer than image analysis. Models require approximately 312 MB of downloads; Python dependencies, particularly GPU PyTorch, need additional disk space.

Subsequent runs keep compatible installed packages, reuse the downloaded models, and analyze only new or changed image content. **Add more images and run the same file again.** Each run creates a separate dated export folder without overwriting older exports.

Windows with Python 3.12 is the tested platform. Python 3.11 is accepted by the installer. The Python entry point can also be invoked on other supported platforms, but those operating systems have not been validated end to end for this package.

## What each run writes

By default, each run creates its own dated subfolder inside `exports`, keeping that run's files together:

```text
exports/
  export_2026-09-22_14-30-15_123456/
    export_2026-09-22_14-30-15_123456.csv
    export_2026-09-22_14-30-15_123456_run.json
    export_2026-09-22_14-30-15_123456_contactsheet.jpg
```

The folder and filenames share a local date/time timestamp that includes microseconds, so multiple runs on the same day get separate folders. Inference timestamps inside the CSV use UTC. Existing exports from earlier versions are left in place; they are not moved.

- **CSV:** one row for every image currently in the selected input folder, including cached results. It contains each model's counts, count votes and averages, the combined output, per-person details, model evidence, devices, and timings. Detailed arrays are preserved in JSON cells, so a separate person CSV is unnecessary.
- **Run JSON:** configuration and model hashes, image/error/cache totals, elapsed time, and the contact-sheet panel-to-filename mapping.
- **Contact sheet:** YOLOE boxes and translucent instance masks, pose keypoints, and combined apparent-facing labels. Selection favors new/changed images and varied detected objects, group sizes, directions, and model disagreements; cached images fill any remaining places. Fewer than 20 images produces a smaller sheet. This is a review sample, not a random sample for estimating accuracy.

The contact sheet displays YOLOE and pose overlays. The independent YOLO26n and MegaDetector results remain available in the CSV evidence.

The CSV uses UTF-8 with a BOM for spreadsheet compatibility. Large `persons_json` or `expert_evidence_json` cells can exceed Excel's 32,767-character cell limit. The CSV retains the full text; use Python or another CSV reader when inspecting or round-tripping detailed evidence. See [CSV schema and interpretation](docs/CSV_SCHEMA.md).

## Select an input folder and options

Drag a folder onto `run_analysis.cmd`, or pass a quoted folder path:

```powershell
.\run_analysis.cmd "D:\Trail Photos\Camera 1"
```

Use explicit input and output options when desired:

```powershell
.\run_analysis.cmd --input "D:\Trail Photos\Camera 1" --output "D:\Trail Exports"
```

`--output` selects the parent export directory; the program creates a new dated subfolder inside it for each run. In the example above, all files for one run appear under `D:\Trail Exports\export_YYYY-MM-DD_HH-MM-SS_microseconds\`. The `output_dir` setting below has the same meaning.

Relative paths are resolved from the repository folder. Input, output, cache, and model folders must be distinct. Generated output/model/cache folders are excluded from recursive image discovery.

| Option | Behavior |
|---|---|
| `--no-contact-sheet` | Skip contact-sheet export for this run. Enabled by default. |
| `--contact-sheet-size 20` | Maximum review panels; accepts 1–100. |
| `--device cpu` | Force CPU inference, including the attribute model. |
| `--device auto` | Use working CUDA for detectors/pose when available; otherwise CPU. Default. |
| `--device cuda` | Try CUDA with the same safe CPU fallback if unavailable. |
| `--threads 8` | CPU inference thread setting. Default 8. |
| `--no-recursive` | Analyze only files directly in the input folder. |
| `--export-new-only` | Include only images actually analyzed in this run in the CSV. |
| `--force` | Reanalyze all selected images instead of reusing inference results. |
| `--offline` | Prohibit dependency/model downloads; requires completed setup. |
| `--models "D:\Models"` | Use another model-cache directory. |
| `--cache "D:\Trail Cache"` | Use another inference-cache directory. |

For example, disable the contact sheet and export only newly analyzed images:

```powershell
.\run_analysis.cmd --no-contact-sheet --export-new-only
```

`--export-new-only` affects the CSV. If a contact sheet is enabled, it still samples the current folder inventory and may include cached images to fill the requested panel count.

Set persistent defaults in `settings.json`:

```json
{
  "input_dir": "images",
  "output_dir": "exports",
  "device": "auto",
  "threads": 8,
  "recursive": true,
  "contact_sheet": true,
  "contact_sheet_size": 20
}
```

Change `"contact_sheet": true` to `false` to disable it by default. Command-line flags override these defaults. `--contact-sheet` can re-enable it for one run.

Supported filename extensions are `.jpg`, `.jpeg`, `.png`, `.bmp`, `.tif`, `.tiff`, and `.webp`, case-insensitively. The pipeline analyzes still images; for a multi-frame image file, only the initially opened frame is analyzed. Symlinked files and symlinked subfolders are skipped. Images are decoded with EXIF orientation applied before detecting or cropping.

## How detection works

The full package runs four vision models on each new image, followed by one lightweight attribute-model pass per YOLOE person crop. It does not require training on your images.

| Expert | Role | What it contributes |
|---|---|---|
| **YOLOE-26s segmentation** | Open-vocabulary object detector with fixed trail-related prompts | Canonical person boxes, object counts, and instance masks; also supports strollers, ATVs/UTVs, and other categories absent from standard COCO models. |
| **YOLO26n** | Independent lightweight COCO detector | Comparison counts for people, bicycles, motorcycles, dogs, backpacks, and cars/trucks/buses. |
| **MegaDetector V6 compact** | Detector developed for camera-trap imagery | Independent person count and generic animal/vehicle detections. Its generic animal label does not count as a dog prediction. |
| **YOLO26n pose** | Lightweight 17-keypoint person pose model | Independent person detections and body/face keypoints used by conservative front/back/side and profile-direction rules. |
| **PP-LCNet x1.0 pedestrian attributes** | Lightweight classifier on individual person crops | Front/back/side, backpack presence, and experimental native age and binary-label scores for review. |

YOLOE uses these fixed prompts:

```text
person, bicycle, motorcycle, dog, backpack, baby stroller,
all-terrain vehicle, utility terrain vehicle, car, truck, bus,
golf cart, tractor, kick scooter, suitcase, duffel bag
```

Setup computes their text embeddings once using MobileCLIP2-B and saves a prepared checkpoint. Subsequent image inference uses the prepared checkpoint without loading the text encoder.

Object detections use confidence threshold `0.25`, an IoU setting of `0.5`, FP32 inference, and at most 300 detections per model. Image inference size is 960 pixels, except MegaDetector at 1280. Near-identical competing motor-vehicle labels are additionally deduplicated at box IoU `0.8`. These are working settings, not accuracy guarantees.

### Category mapping

| Export category | YOLOE labels included |
|---|---|
| `people_total` | `person` |
| `bicycles` | `bicycle` |
| `strollers` | `baby stroller` |
| `motorcycles` | `motorcycle` |
| `atv_utv` | `all-terrain vehicle`, `utility terrain vehicle`, `golf cart` |
| `other_vehicles` | `car`, `truck`, `bus`, `tractor` |
| `dogs` | `dog` |
| `backpacks` | `backpack` objects |
| `cars_trucks_buses` | `car`, `truck`, `bus`; a subset of `other_vehicles` |
| `kick_scooters` | `kick scooter` |

`cars_trucks_buses` overlaps `other_vehicles`; do not sum them as separate vehicle categories. Suitcase and duffel-bag detections are retained in the detailed expert evidence. The package does not infer physical bag size or produce a “large backpack” classification.

### Combining experts

Counts are combined separately by category. Unsupported outputs are excluded from a vote; they are never converted to zero.

- **Person count:** YOLO26n, YOLOE, and MegaDetector participate in the comparison vote. A count wins only if at least two experts agree and that count has strictly more than half of the eligible votes. The combined person count deliberately remains the **YOLOE person roster size**, so every per-person age/orientation/backpack total refers to the same set of people. The separate majority vote can disagree with it.
- **Other counts:** YOLO26n and YOLOE vote where both support a category. With two experts, both must agree. If there is no majority, the combined output uses YOLOE as an explicitly labeled provisional fallback. Categories supported only by YOLOE are marked `single_expert`, not consensus.
- **Averages:** the arithmetic mean, participating model count, and maximum-minus-minimum spread are exported independently. Fractional averages are comparison statistics, not estimated fractional people or verified counts.
- **Masks:** YOLOE masks are evidence from the same YOLOE model. They do not receive an additional independent vote. Box containment, proximity, and mask overlap help review which person a backpack may belong to. Spatial association alone does not establish that the person carries it.

The models are not equally validated experts, and shared model families can make correlated mistakes. Current votes use explicit rules without learned reliability weights. Manual labels are needed before choosing category-specific weights or interpreting model agreement as accuracy.

### Person orientation and direction

Pose detections are matched to the YOLOE person roster using mutual-best box IoU of at least `0.5`, with a margin of at least `0.1` over competing matches. Crowded, ambiguous matches remain unknown.

The pose rules are **local, experimental geometry heuristics**, not a trained orientation model. They require reliable torso keypoints, sufficient person size, and compatible face/body geometry. Working gates include keypoint confidence `0.60`, person confidence `0.40`, and resized person height of at least 72 pixels. Back-facing classification needs compatible shoulder/hip ordering; simply missing a face is insufficient. Profile direction requires a coherent nose/eye/ear arrangement. The reported pose evidence score is a minimum input-keypoint confidence, not a calibrated orientation probability.

The attribute classifier independently predicts front, back, or side. A native orientation label is accepted only for a crop at least 80 pixels wide and 160 pixels high, with top score at least `0.8` and top-versus-runner-up margin at least `0.2`.

The combined orientation uses these rules:

| Attribute / pose evidence | Combined output |
|---|---|
| Both known and agree | Agreed orientation; source identifies both experts. |
| One known, one unknown | Available expert; source identifies which one. |
| Both known but disagree | `unknown`, with conflict recorded. |
| Both unknown | `unknown`. |

Front maps to `toward`; back maps to `away`. Side maps to `left` or `right` only when compatible pose-profile evidence provides that direction. Otherwise direction is `unclear`. The labels are relative to the image/camera. A person can face sideways while moving elsewhere; still-image facing is not motion tracking.

### Age, presentation, and backpacks

PP-LCNet's native age bins are `under18`, `18_60`, and `over60`. Native predictions and scores are preserved, with the same minimum-detail, score, and margin gates described above. **Earlier child examples were not classified reliably.** The combined output therefore always uses `age_unknown`, rather than promoting these predictions into accepted adult/child counts. `combined_adults = 0` and `combined_children = 0` mean no ages were accepted, not that the photograph contains no adults or children. The native `under18` bin also includes teenagers.

The model's native binary `Female` training-label score is retained as an explicitly unvalidated experimental presentation proxy. It does not establish a person's gender identity or sex. The combined per-person presentation stays `unclear`.

The backpack classifier accepts presence at scores at least `0.8`, absence at scores at most `0.2`, and otherwise returns unknown; the minimum-detail gate also applies. A positive spatial backpack association conflicting with classifier absence produces unknown. Spatial support alone is insufficient to claim carrying. **Detected backpack objects** and **people classified as carrying a backpack** are separate quantities and may differ.

## Incremental processing and repeated exports

The cache keys successful predictions by the image's SHA256 content hash and a configuration fingerprint covering code, model content, runtime package versions, requested device, and thread settings. Replacing an image with changed bytes triggers reanalysis. Changing relevant configuration or implementation also invalidates old predictions. Use `--force` when deliberately repeating inference.

Each normal export is a snapshot of the **currently selected folder**, not an append-only visitor database. Previously analyzed images still present in that folder are included from cache. Removed images are absent from the next snapshot, while old export files remain unchanged. An unchanged run still creates a new dated subfolder containing a new snapshot and, unless disabled, a new contact sheet.

Identical image bytes under different filenames can share cached inference, but still produce separate CSV rows. Different selected folders may reuse the content cache. **Counts represent appearances in photographs, not unique people, visits, or trail passages.** Summing overlapping snapshots or repeated photos will double-count appearances.

Failed and partially failed inference results are exported with error information and retried on the next run. Successful results already cached before an interrupted run can be reused. If a run is forcibly closed, remove `.cache/run.lock` only after confirming that no analysis process is still running.

## GPU, CPU, installation, and offline use

On a fresh setup, the installer checks NVIDIA driver capability and chooses a supported CUDA PyTorch build when possible; otherwise it installs CPU PyTorch. Runtime checks execute a real CUDA kernel. Unsupported hardware, unavailable drivers, or CUDA execution failures cause detector/pose fallback to CPU. AMD GPUs and Apple Metal are not accelerated by this implementation.

Paddle's CPU package is the default for the small attribute classifier. A compatible preinstalled `paddlepaddle-gpu` build inside this package's environment is recognized and tried, with CPU fallback. Actual detector/pose and attribute devices are recorded separately; GPU detection does not imply every component runs on the GPU.

To install dependencies and prepare models without analyzing any images:

```powershell
.\setup.cmd
```

To repair or reselect the PyTorch build after adding a GPU or updating its driver:

```powershell
.\setup.cmd --repair-torch
```

For a CPU-only install, use `--cpu-install` on the first setup. To replace an already installed Torch build with CPU wheels, use:

```powershell
.\setup.cmd --cpu-install --repair-torch
```

After setup, offline operation is available:

```powershell
.\run_analysis.cmd --offline
```

An offline first installation additionally requires compatible Python package wheels and model files to be transferred to the target computer. A `.venv` directory is not a portable installation to copy between computers. For an ordinary connected second computer, clone/download the code and let its launcher create a fresh environment.

The Python launcher equivalent is `python bootstrap.py`; after setup, the environment's Python can call `python -m trailcam` directly. Direct module invocation assumes dependencies are installed. On Windows, the explicit command is:

```powershell
.\.venv\Scripts\python.exe -m trailcam --help
```

### Analysis time

Earlier component measurements on an **Intel Core i9-11900K, using eight CPU threads**, estimated approximately **5–6 minutes for 157 photographs** for the full non-LLM expert set. This is an estimate assembled from measured components, not a hardware-independent promise or a fresh benchmark of this packaged launcher. The package now combines attribute outputs into one classifier pass, reducing duplicate work.

The packaged application was also tested on 20 selected images (including crowded scenes) using Windows, an Intel i9-11900K with eight CPU threads, and an RTX 3090:

| Run | Analysis/export time | Complete launcher time |
| --- | ---: | ---: |
| GPU detectors/pose + CPU attributes, contact sheet enabled | 14.7 seconds | Not separately measured |
| All CPU, contact sheet disabled | 37.5 seconds | 43.6 seconds |
| All 20 results cached, contact sheet disabled | 2.3 seconds | 8.0 seconds |

These are throughput measurements, not accuracy measurements; the GPU/CPU runs used different contact-sheet settings. Both new-image runs completed with zero processing errors. All 54 unit/integration tests passed, and a fresh isolated installation downloaded and verified every model.

Initial dependency installation, model downloads, and prompt preparation are additional. Runtime depends on image size, person count, hardware, and cache state. Cached runs avoid model inference. Read each run's JSON for total elapsed time and its CSV for actual per-image analysis times and devices.

## Troubleshooting

| Symptom | Action |
|---|---|
| Python is missing or the wrong version is selected | Install 64-bit Python 3.12 or 3.11. The Windows launcher checks the existing environment, then the Python launcher, then `python`. |
| Download or pip installation fails | Check internet/proxy access and available disk space, then rerun. Existing compatible packages and verified model files are reused. |
| Model checksum fails | A download may be incomplete or altered. Rerun setup online; `--offline` cannot repair missing or invalid model files. |
| An expected GPU is not used | Check the recorded device and fallback messages. Update the NVIDIA driver if needed, then run `setup.cmd --repair-torch`. CPU inference remains available. |
| Analysis reports another run is active | Wait for it to finish. After a confirmed crash, remove the stale `.cache/run.lock`. |
| Some images fail | Inspect `status` and `error` in the CSV. Other images continue; failed images are retried next time. |
| Contact-sheet export fails | The CSV is saved first. Check the run JSON's `contact_sheet_error`; use `--no-contact-sheet` if necessary. |
| Window closes before messages can be read | Open PowerShell in the repository and run `.\run_analysis.cmd` there. |

## Development, privacy, and licenses

Run the regression tests with:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Tests cover cache/export behavior, inference plumbing, confidence gates, and combination invariants. They do not establish accuracy on a deployment's camera images. Review the generated contact sheets and manually label representative and difficult examples before relying on counts or demographic estimates.

The public repository contains code and documentation. Model weights are downloaded from their upstream sources. Your images, model cache, Python environment, inference cache, exports, and contact sheets are excluded from version control by the supplied `.gitignore`. Inference runs locally; the package does not upload photographs. Generated CSVs contain filenames and visual evidence, and contact sheets contain the photographs themselves, so share outputs deliberately.
